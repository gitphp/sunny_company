分层已经按你给的职责拆完：控制器只做校验和编排，数据库和业务规则都在 Service。

**控制器**
- 不再查库、写库、开事务
- 注入对应的一个 Request + 一个 Service，校验后把参数交给 Service
- 权限仍走路由上的 `permission:` 中间件

**Request（每个控制器一个，按场景校验）**
- `UserRequest`、`RoleRequest`、`DepartmentRequest`、`AuthRequest`、`MenuRequest`、`PermissionRequest`、`OptionRequest`
- 场景名等于 action 名（如 `storeRules()`、`changeStatusRules()`）
- 只做字段级校验：必填、格式、长度、唯一性
- 已删除原来的 `Store*` / `Update*` / `LoginRequest`

**Service（查库 + 业务校验 + 事务）**
- `UserService`：分页/导出、增删改、不能操作自己、非超管不能赋超管角色
- `RoleService`：系统角色不可删、超管不可禁用、菜单祖先补全、事务内同步权限
- `DepartmentService`：父级循环校验、有下级不可删
- `AuthService`：登录鉴权、会话、当前用户与侧边栏菜单（已吸收原 `UserAuthenticator`）
- `MenuService` / `PermissionService` / `OptionService`：树与下拉数据

复杂规则（不能删自己、不能选自己当父部门等）都在 Service 里用 `ValidationException` 抛出，不再写在控制器。
